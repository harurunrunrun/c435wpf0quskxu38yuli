連結成分の統合を履歴に残し、指定した時点まで元に戻します。

別名：Rollback Union-Find / Rollback DSU / Undo Union Find

## 使う場面

辺の追加と削除を含む連結性の問い合わせで、すべての操作が事前に分かる場合に使います。通常のUnion-Findは辺の削除を扱えませんが、ある範囲で行った統合をまとめて元に戻せれば、再帰的な処理を組み立てられます。過去の状態が枝分かれする場合も、その関係を木として探索できます。

## 考え方

統合するときに、変更する根の親とサイズを履歴へ保存します。再帰へ入る前の履歴の長さを記録し、戻るときにその長さまで変更を逆順に取り消します。

動的な連結性では、各辺が存在する時間区間を求め、時間に対するセグメント木へ載せます。ノードへ入るときにその区間で常に存在する辺を統合し、葉で問い合わせに答えます。ノードから出るときに巻き戻します。

## 適用条件

以下の実装は経路圧縮をせず、サイズの小さい成分を大きい成分へ付けます。経路圧縮は親を書き換える箇所が増え、巻き戻しを含む操作列では通常のならし計算量をそのまま使えません。

同じ成分同士の統合では履歴を増やしません。そのため、統合を呼んだ回数ではなく、保存した履歴の長さまで戻します。成分数や成分の合計値も管理するなら、その変更も履歴に保存します。

## なぜ正しいか

変更前の値を逆順に戻すと、各統合の直前の状態を正確に復元できます。したがって、保存した履歴の長さまで戻せば、再帰へ入る前の状態と一致します。

時間のセグメント木の葉では、その時刻に存在するすべての辺が祖先のどこかで統合されています。存在しない辺は統合されていないため、その時刻のグラフと同じ連結成分になります。

## 計算量

サイズで統合するため、`find` と統合は最悪 $O(\log N)$ です。履歴1件の復元は $O(1)$ です。$Q$ 時刻、辺の生存区間が $E$ 個なら、時間のセグメント木への登録は $O(E\log Q)$ 件になり、全体は $O(E\log Q\log N+Q\log N)$ 時間です。

## 実装

統合前に `snapshot()` で履歴の長さを保存し、その処理が終わったら `rollback(snapshot)` を呼びます。頂点は0から $N-1$ で番号を付けます。以下のコードはUnion-Find部分で、時間区間を登録するセグメント木は別に作ります。

```cpp
#include <bits/stdc++.h>
using namespace std;
struct RollbackDSU {
    vector<int> p; vector<array<int,4>> hist;
    explicit RollbackDSU(int n):p(n,-1) {}
    int find(int x) const { while(p[x]>=0) x=p[x]; return x; }
    int snapshot() const { return hist.size(); }
    bool merge(int a,int b) {
        a=find(a); b=find(b); if(a==b) return false;
        if(p[a]>p[b]) swap(a,b);
        hist.push_back({a,p[a],b,p[b]}); p[a]+=p[b]; p[b]=a; return true;
    }
    void rollback(int mark) {
        assert(0<=mark && mark<=int(hist.size()));
        while(int(hist.size())>mark) {
            auto z=hist.back(); hist.pop_back(); p[z[0]]=z[1]; p[z[2]]=z[3];
        }
    }
    int size(int x) const { return -p[find(x)]; }
};
```
